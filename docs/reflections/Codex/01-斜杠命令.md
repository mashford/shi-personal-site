# 斜杠命令：在聊天框里控制 Codex

斜杠命令是以 `/` 开头的快捷操作。它们不是发给模型的普通问题，而是让 Codex 切换模式、选择模型、压缩上下文或打开工具面板。

## 基本用法

在 Codex 桌面 App 的输入框中：

```text
/
```

然后输入命令名称，选择候选项并按 Enter。也可以直接输入完整命令，例如：

```text
/status
/plan 先分析这个登录问题，不要修改文件
/review
```

命令列表会根据当前环境变化。桌面 App、CLI、IDE 扩展和 ChatGPT 网页端并不一定提供完全相同的命令。

## 命令总览

| 命令 | 作用 | 常见时机 |
| --- | --- | --- |
| `/plan` | 进入计划模式 | 任务涉及多个步骤或多个文件时 |
| `/goal` | 设置、查看、修改、暂停或清除持久目标 | 长任务、需要跨多轮推进时 |
| `/model` | 选择模型 | 需要在速度、质量、推理能力之间取舍时 |
| `/reasoning` | 选择推理强度 | 简单任务想快一点，复杂任务想多分析时 |
| `/fast` | 开关 Fast 服务层（如果当前模型提供） | 已知任务简单且更在意响应速度时 |
| `/permissions` | 调整 Codex 可执行操作的审批策略 | 只读、自动批准或更严格控制时 |
| `/approve` | 重试最近一次被自动审查拒绝的操作 | 确认操作安全且需要重新执行时 |
| `/status` | 查看当前会话、模型、权限和上下文状态 | 不确定当前环境时 |
| `/compact` | 压缩当前对话上下文 | 长对话变慢或接近上下文上限时 |
| `/ide-context` | 开关共享的 IDE context | 想让桌面 App 使用编辑器中的文件/选区时 |
| `/local` | 选择本地项目执行 | 需要读写本机文件时 |
| `/cloud` | 把任务放到云端执行 | 想让任务脱离本机持续运行时 |
| `/cloud-environment` | 选择云端环境 | 云端需要特定依赖或项目环境时 |
| `/project` | 选择项目 | 新聊天需要绑定到某个本地项目或项目空间时 |
| `/worktree` | 在 Git worktree 中运行 | 想隔离修改，避免影响当前工作目录时 |
| `/mention` | 添加文件到当前对话 | 需要明确指定文件或目录时 |
| `/init` | 生成 `AGENTS.md` 初始文件 | 第一次给项目建立 Codex 规则时 |
| `/mcp` | 查看 MCP 连接和状态 | 需要外部工具、文档或服务时 |
| `/skills` | 浏览和使用可用 Skill | 想调用某个专门工作流时 |
| `/memories` | 配置记忆的使用或生成 | 当前账号/版本支持 Memories 时 |
| `/diff` | 查看工作区 Git 差异 | 修改后想检查范围时 |
| `/review` | 审查当前改动 | 提交前、测试后或需要第二轮检查时 |
| `/ps` | 查看后台终端及最近输出 | 任务启动了 dev server 或长命令时 |
| `/stop` | 停止当前会话启动的后台终端 | 需要清理正在运行的进程时 |
| `/feedback` | 提交反馈和诊断日志 | 遇到产品问题时 |
| `/fork` | 从当前聊天复制出一个新聊天 | 想尝试另一种方向但保留原聊天时 |
| `/side` / `/btw` | 开一个临时侧边聊天 | 只想问一个不打断主线的小问题时 |
| `/new` | 在当前本地工作区开始空白聊天 | 想保留项目但清空当前对话时 |
| `/archive` | 归档当前聊天 | 整理历史聊天时 |
| `/share` | 创建当前聊天的分享快照 | 想把结果发给别人查看时 |
| `/usage` | 查看使用量/计费信息 | 检查额度时 |

不同版本可能还会显示 `/chat`、`/pin`、`/rename`、`/pet` 等界面管理命令。最可靠的方式是输入 `/` 查看当前列表。

## 你截图中的菜单对应关系

截图里显示的是用户界面名称，不一定直接显示命令名：

| 菜单显示 | 通常对应 | 说明 |
| --- | --- | --- |
| Code review | `/review` | 审查未提交改动或与分支比较 |
| Compact | `/compact` | 压缩当前聊天上下文 |
| Fast | `/fast` | 切换 Fast 服务层（如果可用） |
| Feedback | `/feedback` | 提交反馈 |
| Fork chat | `/fork` | 从当前聊天创建分支 |
| Goal | `/goal` | 设置持续目标 |
| IDE context | `/ide-context` | 打开或关闭共享 IDE 上下文 |
| MCP | `/mcp` | 查看 MCP server 状态 |
| Model | `/model` | 选择模型 |
| Plan mode | `/plan` | 打开计划模式 |
| Reasoning | `/reasoning` | 选择推理强度 |
| Share chat | `/share` 或菜单动作 | 创建聊天快照；是否支持命令取决于当前版本 |

当菜单显示 `IDE context — Turn IDE context off` 时，说明它当前是打开状态；再次点击会关闭。关闭后，桌面 App 的下一条消息不会自动带上编辑器上下文，但手动附件和 `@文件` 仍然可以使用。

## 最常用的命令详解

### `/plan`：先调查，再改代码

```text
/plan 先分析这个页面为什么在移动端溢出，暂时不要修改文件
```

适合：重构、跨文件修改、视觉还原、部署、数据迁移、难以复现的 Bug。

计划模式的价值不是让 Codex 写一份漂亮计划，而是把“它目前知道什么、还缺什么证据、准备如何验证”先暴露出来。计划确认后，再让它实施：

```text
计划没问题，按计划实施，并在完成后运行相关测试。
```

### `/goal`：把任务变成持续目标

```text
/goal 完成页面视觉还原，桌面和移动端截图都通过，未知之处必须停下来询问
```

常用操作：

```text
/goal                 # 查看当前目标
/goal edit            # 修改目标
/goal pause           # 暂停目标
/goal resume          # 恢复目标
/goal clear           # 清除目标
```

目标适合长任务，不适合每一个小改动。目标文字要写“完成条件”，例如“测试通过”或“截图差异低于某个阈值”，不要只写“把它做好”。

### `/status`：先确认自己在哪里

```text
/status
```

当你不确定当前使用的模型、项目目录、权限、上下文容量或会话状态时，先执行它。很多“Codex 怎么突然看不到文件”的问题，实际上是当前聊天切到了另一个项目或云端环境。

### `/compact`：长对话的整理按钮

```text
/compact
```

它会把较早的对话压缩成更短的工作摘要，以腾出上下文空间。压缩前应把重要决定写进项目文件、`AGENTS.md` 或任务说明里，不要只依赖聊天历史。

### `/review`：让 Codex 以审查者视角再看一次

```text
/review
```

它通常会让 Codex 检查 Git 工作区中的改动，并按问题严重程度给出反馈。它是审查，不等于自动修复；看完结果后，再明确说“修复这些问题并重新验证”。

### `/ide-context`：开关编辑器上下文

```text
/ide-context
```

打开后，桌面 App 可以使用已连接 IDE 中当前打开的文件和选区。它不是“把整个仓库都上传”，也不是永久记忆。需要精确指定内容时，仍然使用文件附件或 `@` 文件引用。

## 一个安全的常用组合

```text
/status
/plan
/ide-context
/permissions
/goal
```

实际顺序可以按任务调整。不要为了使用命令而使用命令；命令的意义是减少猜测、限制范围和增加可验证性。
