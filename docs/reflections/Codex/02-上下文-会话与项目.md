# 上下文、会话与项目

很多人第一次使用 Codex 时，会把“聊天记录”“项目目录”“IDE context”和“文件附件”混成一个东西。它们都会影响 Codex，但作用不同。

## Context 是什么

Context 是 Codex 当前可以参考的信息，可能包括：

- 当前聊天中的文字和图片；
- 当前项目中 Codex 已经读取过的文件；
- 通过 `@`、`/mention` 或附件明确加入的文件；
- IDE 中打开的文件和选中代码；
- 工具输出，例如测试结果、Git diff、浏览器截图；
- `AGENTS.md`、Skill 和配置提供的规则。

Context 不是“项目全部内容”。为了控制成本和减少误读，Codex 通常会按任务需要搜索和读取文件。你越明确指出入口文件、复现步骤和完成条件，结果越稳定。

## IDE context

### 它会带来什么

在桌面 App 中打开 IDE context 后，Codex 可以获得编辑器当前的工作上下文。典型内容是：

```text
当前打开的文件：src/App.tsx
当前选区：第 40–62 行
当前工作区：/path/to/project
```

它特别适合：

```text
解释我当前选中的这段代码
修复当前文件中的这个 TypeScript 错误
根据我正在看的组件补一个测试
```

### 它不会做什么

- 不会自动理解整个仓库；
- 不会代替 Git；
- 不会把所有打开文件永久写进记忆；
- 不会保证桌面 App、CLI 和 IDE 扩展拥有完全相同的界面；
- 不会自动解决缺少运行环境或权限的问题。

桌面 App 的命令是 `/ide-context`；CLI 或 IDE 侧常见的是 `/ide`，它表示把打开文件、当前选区等 IDE 信息加入下一次提示。

## 文件引用：`@` 和 `/mention`

### `@`：快速添加路径

在 Codex 输入框中输入 `@`，选择项目中的文件或目录：

```text
请检查 @src/components/Header.tsx 和 @src/styles/header.css，解释为什么标题没有垂直居中。
```

适合在提示中直接表达“这个文件就是证据”。

### `/mention`：通过命令添加

```text
/mention
```

选择文件后，再继续输入任务。它适合你想先添加上下文、再慢慢组织问题的情况。

### 怎么选

| 情况 | 建议 |
| --- | --- |
| 正在编辑的文件和选区已经足够 | IDE context |
| 想明确指定几个文件 | `@文件路径` |
| 想把一个完整文件附加到当前聊天 | `/mention` 或 IDE 命令 `chatgpt.addFileToThread` |
| 需要截图或设计稿 | 直接上传图片，并说明视口尺寸 |
| 需要整个仓库的架构 | 让 Codex 先扫描项目，再指定关键入口，不要一次性粘贴全部代码 |

## 会话命令

### `/new`

在当前本地工作区开一个新的聊天。它保留项目目录，但不会把旧聊天的全部推理过程当作新聊天历史。

适合：任务目标完全变化、旧对话太长、想保持同一项目但重新开始。

### `/resume`

恢复已保存的会话：

```text
/resume
```

在 CLI 中：

```bash
codex resume
codex resume --last
```

`--last` 通常会恢复当前工作目录下最近的会话；如果你需要选择其他目录的会话，要显式查看并选择，不要假设当前目录一定正确。

### `/fork`

从当前聊天复制一个新聊天。原聊天保留，新聊天继承到分叉点的历史。

适合：保留“方案 A”，另开一条尝试“方案 B”。不适合用来代替 `/new` 清理完全无关的聊天。

### `/side` / `/btw`

开一个临时侧边聊天，用来问一个小问题，例如：

```text
/side 这个 API 错误可能还有哪些原因？不要修改当前项目。
```

它适合短暂调查，不应该承载主任务的关键决定，除非你之后把结论带回主聊天。

### `/compact`

压缩长对话的历史。压缩以后仍应检查 Codex 是否保留了关键目标、路径和验证要求。重要信息应该落在项目文件或 `AGENTS.md` 中。

## 项目与执行位置

### 本地项目

本地项目通常对应 IDE 打开的文件夹或 Codex 选择的本地目录。Codex 可以在权限允许时读写文件、运行测试和访问本地服务。

### 云端环境

云端任务在远程环境中执行。它适合不需要你本机特殊环境的长任务，但本机未提交的文件、未上传的资源和本地服务不一定可见。

### `/project`

选择新聊天要使用的项目。项目决定默认文件来源和工作上下文，不等于单纯给聊天改一个名字。

### `/local`、`/cloud`、`/cloud-environment`

```text
/local
/cloud
/cloud-environment
```

使用它们前先问自己：

```text
任务需要本机文件、浏览器、私有凭证或本地 dev server 吗？
```

如果需要，优先本地；如果只是独立代码任务，且希望脱离本机继续运行，可以考虑云端。

### `/worktree`

在 Git worktree 中隔离一个任务：

```text
/worktree
```

适合并行开发、实验性重构和不想污染当前工作目录的改动。使用前确认你的仓库和 Git 工作流允许创建 worktree。

## 项目级上下文：`AGENTS.md`

聊天历史会变短、会被压缩，也可能换一条聊天；项目规则应该放在可提交的文件里：

```text
AGENTS.md
```

内容可以包括：

- 项目启动、测试和构建命令；
- 不应修改的目录；
- 代码风格和组件约定；
- 完成任务前必须执行的验证；
- 不确定时必须停下询问的规则。

在项目根目录运行：

```text
/init
```

Codex 会生成初始骨架。生成后一定要人工检查和修改，不能把自动生成的内容当成项目真相。
