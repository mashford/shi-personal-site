# Reasoning：选择推理强度

菜单名称：`Reasoning`
常用命令：`/reasoning`

## 它做什么

Reasoning 控制模型在当前任务上投入多少推理。截图中的 `Extra High` 表示当前选择了较高的推理强度。

```text
/reasoning
```

不同模型和客户端可能使用不同的档位名称。以当前菜单实际显示为准。

## 选择原则

| 任务 | 推理建议 |
| --- | --- |
| 改一个拼写、查一个文件 | 低或默认 |
| 普通 Bug、测试、局部重构 | 中等 |
| 跨文件架构、复杂调试 | 高 |
| 视觉还原、长任务、需要比较多个方案 | 高或 Extra High |

更高推理通常意味着更长等待和更多用量。它也不能替代：

- 设计稿或截图证据；
- 正确的项目路径；
- 明确的约束；
- 实际运行测试；
- 用户对未知行为的确认。

## 让高推理真正有效

不要只把档位调高，还要同时提供：

```text
目标：我要改变什么
上下文：相关文件、截图、报错、复现步骤
约束：不能改变什么，哪些操作需要确认
完成条件：什么证据出现时才算完成
未知处理：缺少证据时停下来询问，不要猜
```

## 与 Fast 的区别

Fast 主要偏向服务速度；Reasoning 主要控制推理投入。它们不是同一个开关，也不是简单的“快/慢”互换。
