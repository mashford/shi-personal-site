# Compact：压缩聊天上下文

菜单名称：`Compact`
常用命令：`/compact`

## 它做什么

Compact 会把较早的聊天内容压缩成更短的摘要，以释放上下文空间。它适合长任务，不是删除项目文件，也不是撤销代码修改。

```text
/compact
```

压缩后，当前任务通常可以继续；但过早对话中的细节可能不再以原文形式存在。

## 什么时候使用

- 对话已经很长，回复开始变慢；
- 任务已经完成了若干阶段，还要继续迭代；
- 你希望保留目标、决定和当前进度，但减少旧日志；
- Codex 提示上下文接近上限。

## 使用前先保存重要信息

不要只把关键决定留在聊天里。压缩前可写入：

- `AGENTS.md`：长期项目规则；
- `docs/task.md`：当前任务目标和完成条件；
- 测试报告：已经验证过什么；
- Git diff：当前实际改动；
- 设计稿或截图：视觉依据。

示例：

```text
请把当前已确认的目标、改动文件、剩余问题和验证命令整理到 docs/task.md，然后再执行 /compact。
```

## 压缩后怎么继续

```text
请先阅读 docs/task.md、当前 git diff 和最近的测试结果，再继续任务。
如果摘要与文件证据冲突，以文件和测试结果为准。
```

## 它不会做什么

- 不会让模型获得新的项目文件；
- 不会修复上下文中原本不存在的信息；
- 不会替代 Git 提交；
- 不会保证每一句旧对话都被逐字保留。

对于视觉还原、部署和跨多个阶段的任务，压缩前写一份可读的任务文件尤其重要。
