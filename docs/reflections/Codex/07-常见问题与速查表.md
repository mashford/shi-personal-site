# 常见问题与速查表

## 桌面 App、IDE、CLI 和云端有什么区别

| 场景 | 适合做什么 | 关键上下文 |
| --- | --- | --- |
| Codex 桌面 App | 管理多个项目、聊天、长任务、本地和云端切换 | 选中的本地项目、聊天、IDE context |
| IDE 扩展 | 边看代码边修改和审查 | 当前工作区、打开文件、选区 |
| CLI | 脚本、终端、自动化、远程开发 | 当前目录、命令行参数、文件引用 |
| 云端 | 脱离本机执行较长任务 | 云端环境中的仓库和配置 |

它们可以共享一部分会话和配置，但不要假设所有本地文件、未提交改动、本地服务和凭证会自动出现在云端。

## 为什么我输入的命令没有出现

按顺序排查：

1. 你是在桌面 App、IDE、CLI 还是 ChatGPT 网页端？
2. 在当前输入框输入 `/`，看当前环境实际支持的命令。
3. 检查项目是否已经打开或选择。
4. 检查是否处于本地、云端或只读环境。
5. 更新 Codex App、CLI 或 IDE 扩展。
6. 重新启动当前客户端；Skill 或配置更新后，重启通常比反复发送提示更可靠。

官方文档明确说明，命令可用性会根据环境和访问权限变化。

## 为什么 IDE context 不见了

可能原因：

- IDE 扩展没有安装、被禁用或没有登录同一账号；
- 编辑器没有打开项目文件夹；
- 桌面 App 没有连接到当前 IDE；
- 当前聊天是云端任务，不是本地项目聊天；
- IDE context 开关被关闭。

恢复步骤：

1. 在 VS Code、Cursor 或 Windsurf 中打开项目目录。
2. 确认 OpenAI Codex 扩展已启用。
3. 用 `Cmd/Ctrl + Shift + P` 打开命令面板。
4. 执行 `Codex: Open Codex Sidebar`。
5. 在编辑器中打开文件或选中代码。
6. 在桌面 App 输入 `/ide-context`，或从 IDE 侧边栏启动当前聊天。

如果仍然没有按钮，先用 `+` 添加文件，或用 `@路径` 精确引用文件。这样可以继续工作，不必把所有问题都阻塞在 IDE context 上。

## `/compact` 后 Codex 好像忘了东西

压缩会减少可见历史。把重要信息写进：

- `AGENTS.md`；
- 任务说明 Markdown；
- GitHub Issue；
- 测试或验证报告；
- 明确附加的文件。

然后重新提示：

```text
请先阅读 docs/task.md 和当前 git diff，再继续完成目标。不要假设压缩前的细节仍然存在。
```

## Codex 修改了我没要求的文件怎么办

```text
/diff
```

然后检查：

```bash
git status --short
git diff --stat
git diff
```

不要立刻提交或推送。先让 Codex 解释每个额外文件为什么被修改；解释不充分的改动应当回退或人工处理。

## 我应该什么时候使用 `/goal`

适合：

- 需要多个阶段才能完成的工作；
- 需要持续验证和迭代的视觉任务；
- 需要跨多个会话继续的迁移或重构。

不适合：

- 改一个拼写；
- 查一个 API；
- 只需要一条命令的简单问题。

## 定时任务需要一直开着 Codex App 吗

取决于任务在哪里运行：

- 云端定时任务或云端 Agent：通常不需要一直开桌面 App；
- 本地文件、IDE context、本地浏览器或本地脚本：需要电脑在线，并保持相应的本地环境可用；
- 纯网站可用性巡检：更适合云端定时任务、CI 或专门监控服务，而不是依赖桌面 App 常驻。

先区分“定时触发”与“本地执行”：定时器负责什么时候开始，执行环境决定它能看到什么。

## 一个适合日常开发的速查表

| 你的目的 | 命令/操作 |
| --- | --- |
| 查看当前环境 | `/status` |
| 先分析不修改 | `/plan`，然后明确“暂时不要改文件” |
| 持续推进大任务 | `/goal` |
| 引用具体文件 | `@路径` 或 `/mention` |
| 使用当前编辑器文件 | `/ide-context` 或 IDE 侧的 `/ide` |
| 换模型 | `/model` |
| 调整推理强度 | `/reasoning` |
| 控制审批 | `/permissions` |
| 查看 Git 改动 | `/diff` |
| 请求审查 | `/review` |
| 查看后台任务 | `/ps` |
| 停止后台任务 | `/stop` |
| 压缩长对话 | `/compact` |
| 开新聊天 | `/new` |
| 恢复聊天 | `/resume` 或 `codex resume` |
| 建立项目规则 | `/init`，再编辑 `AGENTS.md` |
| 查看外部工具 | `/mcp` |
| 选择可复用工作流 | `/skills` 或 `$skill-name` |
| 分享当前聊天 | `/share` 或命令菜单中的 `Share chat` |

## 最后一条经验

给 Codex 的提示最好同时写出：

```text
目标：我要改变什么
上下文：相关文件、截图、报错、复现步骤
约束：不能改变什么，哪些操作需要确认
完成条件：什么证据出现时才算完成
未知处理：缺少证据时停下来询问，不要猜
```

这五项比单纯更换模型或把推理档位调到最高更能减少返工。
